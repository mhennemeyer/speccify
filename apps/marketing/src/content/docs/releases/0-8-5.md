## Modules per spec, overlaps on the board

Several agents working on one project collide when two specs change the same
part of the system at once. This version makes that visible before it happens.

- **A project names its modules** — its architecture map — as `modules` in
  `.agent/settings.json`: a slug, a line of description, optional paths.
  **Module…** above the board edits the list; it is versioned with the project.
- **A spec names the modules it touches** in its front matter:
  `modules: terminal, board`. The editor sheet has a field for it with the
  catalogue as suggestions.
- **Cards warn about overlaps.** A module that another spec in Doing names too
  shows as a red chip — `⚠ terminal · auch #12` — and the inspector says which
  spec and who owns it. Backlog specs are compared against Doing as well, so the
  warning is there before you move a spec. Done never counts. Modules missing from
  the catalogue are marked; without a catalogue the board says so.
- **Workflow policy v11** ("Modules and parallel work"): the agent keeps the
  field, compares a spec's modules with everything in Doing before it starts and
  reports overlaps instead of starting silently; when cutting specs it keeps
  modules per spec minimal, and without a module list it proposes one from the
  code structure and asks. **Einrichten** on the workflow banner installs v11.

The app warns, it does not block. See [Specs → Modules](/app/specs/#modules-who-touches-what).

## Update or install

- **From 0.8.1–0.8.4:** check **Environment → Updates**, download 0.8.5, then
  install.
- **From 0.8.0 or earlier:** install the new version once from the
  [download page](/download/). These older versions lack the updater verification key.
- **Linux deb/rpm:** update through your package manager. In-app Linux updates
  apply to AppImage.

Packages cover macOS Apple Silicon, Windows x64 and Linux x86_64/arm64.
macOS packages are Developer ID signed and notarized. Update packages use verified
signatures on all four targets. Windows code signing is separate; SmartScreen may
still warn. Downloads are on the [0.8.5 release page](https://github.com/mhennemeyer/speccify/releases/tag/v0.8.5).

## Verification and scope

Native tests cover reading, creating and saving the `modules` field (normalised,
byte-stable for everything else) and the policy version. The board regression
covers the chips, the overlap between Doing specs and against Backlog, the
inspector's catalogue marks, the editor field and the catalogue sheet including
a rejected name and the missing-catalogue state. Existing specs keep working
without the field. The workspace board and the web board do not show modules yet.
