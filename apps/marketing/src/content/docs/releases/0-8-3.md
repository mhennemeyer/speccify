## Blocked installations explain themselves

**Install and restart** is refused while editors, drafts, running terminals or
actions are still open. The reason used to appear below the button inside the
scrolling update dialog. With long release notes or a small window it could sit
outside the visible area, so the click seemed to do nothing.

The dialog now scrolls only its content. The error message is pinned to the
bottom edge of the dialog and is always visible; a long list of blockers from
several windows scrolls within the message itself. Nothing else about checking,
downloading or installing updates has changed.

## Update or install

- **From 0.8.1 or 0.8.2:** check **Environment → Updates**, download 0.8.3, then
  install when open editors, drafts and running processes are closed.
  Installation restarts Speccify; downloading alone does not.
- **From 0.8.0 or earlier:** install the new version once from the
  [download page](/download/). These older versions lack the updater verification key.
- **Linux deb/rpm:** update through your package manager. In-app Linux updates
  apply to AppImage.

Packages cover macOS Apple Silicon, Windows x64 and Linux x86_64/arm64.
macOS packages are Developer ID signed and notarized. Update packages use verified
signatures on all four targets. Windows code signing is separate; SmartScreen may
still warn. Downloads are on the [0.8.3 release page](https://github.com/mhennemeyer/speccify/releases/tag/v0.8.3).

## Verification and scope

The dialog was checked in a 900 × 420 px window with thirty lines of release
notes and an installation blocked by a running process: the message stayed fully
inside the visible area. The update interface regression, native updater tests and
the complete test suites passed. Installation in the Windows VM and on Linux
remains a separate platform acceptance check.

The published 0.8.2 was updated to the public 0.8.3 on macOS through the in-app
updater: 30,614,837 bytes downloaded, signature verified, installed and
restarted; all four open windows were restored and the installed app kept its
valid Developer ID signature. All four public update URLs and the complete
update manifest were verified against an independent local rebuild. See [0.8.2](/releases/0-8-2/) for
the terminal and agent-settings features this build continues to ship.
