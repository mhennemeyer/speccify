## Workspaces with the right scope

Open a folder of repositories in one workspace window. Group repositories,
follow their specs on a shared board, and keep files, Git operations, actions
and drafts bound to their original repository. Start one terminal in the
parent folder when you need it.

Project discovery now defaults to **depth 1**: the opened folder and its direct
children. Set **1–16** in dashboard Settings to include deeper projects.
Previously discovered reference clones are hidden outside that scope; their
saved names, groups and IDs return when you increase the depth.

[Workspace guide and screenshots](/app/workspaces/)

## One spec register across code branches

Keep `.agent/specs` on a dedicated `specs` branch, mounted at the same path
in each checkout. The desktop app synchronizes that register independently
of the code branch. Specs can show an owner and working branch, changes from
teammates and questions addressed to you. Optional outgoing webhooks report
local workflow events.

Finished specs stay in Done at their existing path. Search the complete
spec list, filter work that needs you, and review tasks and history.

[Specs and team workflow](/app/specs/)

## Clearer handovers and verification

The **Auftrag…** action previews a task and its selected context before you
copy it or paste it into a terminal for submission with Enter. A freshly
started terminal warns you to wait for the host's input prompt before pasting.
Session recovery uses the recorded
session identity where supported and offers an explicit choice otherwise.

CLI and MCP verification share a report that distinguishes successful checks
from readiness on the current platform. Missing tool implementations and failed
checks remain visible. Developer QA can use an opt-in local bridge to inspect
the running desktop app; the bridge is disabled by default.

## Git and the web board

The Git workspace includes a visible commit composer, staged-file and hunk
review, and branch management. Commits apply to the staged index of the
selected repository.

The separate self-hosted web-board service can read multiple spec registers,
update stations and tasks, and expose its board through MCP. It is deployed
separately from the desktop app.

## Downloads and compatibility

- **macOS:** Apple Silicon, macOS 11+, Developer ID signed and notarized.
- **Windows:** x64 NSIS installer and MSI. These builds are not code-signed;
  SmartScreen may warn on first launch.
- **Linux:** x86_64 and arm64, AppImage, deb and rpm. A graphical desktop,
  glibc and WebKitGTK 4.1 are required.

The initial Python environment setup needs an internet connection. Git and
terminal hosts such as Claude Code or Codex must be installed separately.
Automatic updates are not configured in this release; download the installer
from the [release page](https://github.com/mhennemeyer/speccify/releases/tag/v0.7.0).
