## Terminals that survive a restart

During active development the app is rebuilt and restarted many times a day,
and every restart used to end the agent that was running in a project or
workspace terminal. 0.8.7 adds an opt-in terminal preference,
**Terminals überleben App-Neustarts**:

- New terminals then run in a small host process next to the app. Quitting or
  rebuilding the app only disconnects; the agent keeps working.
- On the next start the project or workspace window finds its running session,
  re-attaches, shows the output so far and accepts input — no session dialog,
  no restart of the agent.
- Closing a window deliberately and **Neu starten** still end the session. The
  host process ends itself a minute after the last session is gone.
- Hosted terminals do not block an update installation.

Terminals started before the preference was switched on keep the old
behaviour. Window positions and sizes are now saved shortly after every move or
resize, not only when the app quits, so a hard stop no longer loses them.

## Copying from the terminal

Marked text in the agent terminal can be copied with ⌘C (Windows/Linux:
Ctrl+Shift+C) wherever the focus is in the window. The terminal header confirms
with **Kopiert** or names the reason if it failed. Without a selection Ctrl-C
remains the interrupt signal. ⌥-drag selects text even when a program has taken
over the mouse.

## Bottom terminal in full width

When the terminal is docked at the bottom, it now spans the whole window;
navigator, content and inspector end above it. The right dock is unchanged and
saved layouts keep working.

## Update or install

- **From 0.8.1–0.8.6:** check **Environment → Updates**, download 0.8.7, then
  install.
- **From 0.8.0 or earlier:** install the new version once from the
  [download page](/download/). These older versions lack the updater verification key.
- **Linux deb/rpm:** update through your package manager. In-app Linux updates
  apply to AppImage.

Packages cover macOS Apple Silicon, Windows x64 and Linux x86_64/arm64.
macOS packages are Developer ID signed and notarized. Update packages use verified
signatures on all four targets. Windows code signing is separate; SmartScreen may
still warn. Downloads are on the [0.8.7 release page](https://github.com/mhennemeyer/speccify/releases/tag/v0.8.7).

## Verification and scope

The host process is covered by tests against real PTYs: detaching and
re-attaching replays the output without a gap or duplicate, exit codes reach a
late attach, the initial command is written before the first read, the buffer
keeps its limit, and a dropped client is unregistered. In the bundled macOS app
a counter kept running across quit and reopen and across a rebuild, the window
re-attached from the first line, closing the window ended the session and the
host ended itself 61 s later. Copying was verified with real ⌘C keystrokes into
the system clipboard; the dock geometry with browser regressions for project and
workspace windows.

The host process is compiled for Windows but only exercised on macOS; the
dashboard terminal does not re-attach yet. Windows and Linux installation remain
separate platform checks.

The published 0.8.6 was updated to the public 0.8.7 on macOS through the in-app
updater (31,185,538 bytes, signature verified, both windows restored, valid
Developer ID signature, notarized). A hosted workspace terminal kept its agent
running across that restart and re-attached. All four public update URLs and the
update manifest were verified against an independent local rebuild.
