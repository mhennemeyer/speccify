title: Speccify 0.8.4
description: A blocked update offers "Alles stoppen", finished shells no longer block, and a new search finds newer releases.
---

## A way out of a blocked installation

Speccify refuses to install an update while terminals or actions are running.
Every open terminal counts — also a plain shell after the agent has quit. The
message did not say so, and offered no way forward.

- The message now states how many items are open and that open terminals count.
- **Alles stoppen** sits directly at the message. A second, confirming click ends
  all terminals, running actions and supervised processes. Nothing is installed by
  this button; click **Installieren und neu starten** afterwards.
- Running agents and commands are interrupted. Agent sessions can be resumed after
  the restart; the output of an interrupted command cannot.
- A shell that ended on its own (`exit`) no longer counts as running work. It used
  to block updates until its terminal pane was closed.

Open editors, edited forms and drafts still block installation and are never
closed automatically: save or close them yourself.

## Searching again finds newer releases

Once an update had been downloaded, Speccify stopped searching: a downloaded
0.8.2 hid the published 0.8.3 until the app was restarted. **Jetzt suchen** and the
interval search now work with a finished download. The same version keeps the
verified download; a newer one replaces it and is offered; a failed search keeps
the download and shows the error.

**0.8.1–0.8.3 still behave the old way.** If such a version keeps offering an
outdated update, restart Speccify and search again, or install the downloaded
update first.

## Update or install

- **From 0.8.1–0.8.3:** check **Environment → Updates**, download 0.8.4, then
  install. If the installation is blocked there, close terminals and running
  actions by hand once — the new button arrives with this version.
- **From 0.8.0 or earlier:** install the new version once from the
  [download page](/download/). These older versions lack the updater verification key.
- **Linux deb/rpm:** update through your package manager. In-app Linux updates
  apply to AppImage.

Packages cover macOS Apple Silicon, Windows x64 and Linux x86_64/arm64.
macOS packages are Developer ID signed and notarized. Update packages use verified
signatures on all four targets. Windows code signing is separate; SmartScreen may
still warn. Downloads are on the [0.8.4 release page](https://github.com/mhennemeyer/speccify/releases/tag/v0.8.4).

## Verification and scope

Native tests cover stopping a real terminal session, releasing its workspace claim
and the search behaviour with the real updater against a local feed. The update
interface regression covers the confirmation, the visible position of the button in
a small window and the renewed search. Installation in the Windows VM and on Linux
remains a separate platform acceptance check.
